# 只支持单一币种，用一道检查代替多币种设计

Bittern 的持仓全部是美元，所以不做汇率换算、分币种小计和 `Money(amount, currency)` 类型：它们要多维护一条汇率数据源，还要回答“按哪天的汇率算收益”这类问题，却没有任何实际使用场景。原计划放在路线图阶段 3 的 `Money` 类型也因此取消。

但“不跨币种相加”仍然要保证，否则数据一旦不符合假设，就会静默算出错的数字。这道检查很便宜，因为现成的 `nil → N/A` 路径就能表达它：

- 持仓币种不一致时，`PortfolioSnapshot.make` 的所有合计都是 nil，持仓各自照常显示。按券商筛选到单一币种后，合计会恢复。
- 定投池和历史曲线都是求和，所以同样拒绝混合币种。
- Yahoo 报价币种必须和持仓币种完全一致，否则不使用这个价格。比较区分大小写，因为伦敦股票的 `GBp`（便士）不是 `GBP`。

这也让检查有了第二个用处：它不只防多币种，也能发现 symbol 匹配到另一个市场的报价。

如果以后真的持有非美元资产，界面上会看到合计消失和提示，到那时再决定是否做换算。
